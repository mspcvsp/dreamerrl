# Presenter guide

**Learning Through Imagination** is a 25–30 minute Wood Badge activity for Scouts ages 13–18. Bring two cards labeled LEFT and RIGHT in large print, a sheet to cover them, and the deck. A terminal is optional. Allow about five minutes each for the opening, the maze and the findings, about five minutes for the simulator and the engineering story, and five minutes for the saved-results demo and questions.

Read the figure labels and key numbers aloud. Give Scouts time to think before calling for answers. Scouts can point, speak, write, or signal with their hands. Eight steps can be eight beats counted from a seat. Offer a spoken or written clue in the participant’s preferred format at the start, then use the same neutral count for both directions.

| Slide | What to say or do | Ask the group |
|---|---|---|
| 1 · Can you use AI to build AI? | Introduce two stories. A learning agent practiced in a simulated world. A human directed AI assistants to help build and study it. | Which part of a project would you like help with? |
| 2 · What is AI? | Give examples of identifying a pattern or drafting text. In this lesson the word *agent* means the part that chooses an action. | Which example needs to try something and see what happens? |
| 3 · Learning by trying | Let Scouts suggest a route to camp. Tell them what happened and ask whether they would try it again. What the agent sees or senses is an *observation*. A move it tries is an *action*. Feedback about how well it is doing is a *reward*. Learning to choose moves using that feedback is *reinforcement learning*. | What feedback matters besides getting there quickly? |
| 4 · Maze prediction | Show one LEFT or RIGHT card, then cover it. Count eight neutral beats or steps. At the fork, let Scouts signal their turn. Repeat with the other clue and the same count. Both views at the fork look the same. Before showing results, ask Scouts to predict whether the agent will still have enough information after turning the clue into a short internal summary. | What tells you which way to turn once the clue is covered? How would you test whether the agent remembers it? |
| 5 · A model of the world | DreamerV3 learns an internal model from what it senses and the outcomes of its actions. Think of describing a trail from the landmarks you saw and the turns you took. It uses a compact summary of what it senses and a running summary of earlier events. | Which trail detail is small enough to ignore, and which could decide your next turn? |
| 6 · Practice with predictions | Have Scouts picture what might happen along two routes before moving. DreamerV3 uses predicted experiences to practice its way of choosing actions. That choice rule is called a *policy*. | Suppose the model predicts a bridge where there is none. What might the agent learn from practicing with that prediction? |
| 7 · Recovering the clue | Reveal the three rows in order or point to them one at a time. A separate clue reader guessed LEFT or RIGHT from each part of the tested model. The model’s probabilities still supported perfect recovery at reset. After it drew one compact summary, the reader did about as well as a coin flip. | Why might a system keep some details and drop the one detail we care about? |
| 8 · Using the clue | In a separate test, we chose special starting states for the same trained agents. A clue reader could recover the clue at the turn, while the agents still chose correctly only half the time. | What two things would you measure to tell whether an agent both remembers a clue and acts on it? |
| 9 · A practice network | CAGE2 is a simulated cyber defense setting. A defender gets only part of the picture. An earlier warning might help explain the latest reading. Keep security exercises in approved learning environments. | If a warning disappears from a screen, what evidence would tell you whether the problem is over? |
| 10 · Simulator scores | Read one row aloud, then ask Scouts to compare it with another. One design picks a move directly. The other uses two decision levels. The averages come from three training seeds per design in a fixed simulator comparison. | Does the same design lead in both active opponent scenarios? What can these scores tell us about what the agents remembered? |
| 11 · Who did what? | Microsoft Copilot received text I uploaded manually, separately from VS Code. I also used ChatGPT during the project. OpenAI Codex assisted software development and verification, including implementation, debugging, and tests. DreamerV3 was the agent being studied. The NVIDIA DGX Spark supplied the compute. Git tracks revisions and GitHub hosts the code. | Which tool helped with engineering, which system learned to choose moves, and who decided what counted as evidence? |
| 12 · The human conductor | As technical director I set objectives, weighed approaches, reviewed results, and refined or approved next steps. Use the return arrow to show how a test can send the work back for revision. An earlier plausible plot label needed correction after we traced what the code actually measured. | If an answer sounds confident, what would you check before trusting it or running its code? |
| 13 · Start small | Run the saved-results demo below. Explore AI with your parent or guardian, or work with an Artificial Intelligence merit badge counselor at a troop meeting. | What small project would you try, and how could you check the result? |
| 14 · Build skills | Invite Scouts to choose one skill, such as writing a Python program, explaining a test, or drawing a diagram of how information moves. | What would be easier to verify if you understood the underlying science? |
| 15 · What next? | Invite one idea and one fair test from each group. Younger Scouts can explain the maze in their own words. Interested older Scouts can design a comparison with new mazes and an equal number of LEFT and RIGHT cues. | What result would make you change your explanation? |

## Three-minute saved-results demo

From the repository root, run:

```bash
python3 docs/publication_figures/read_saved_results.py
```

Before reading the output, ask for predictions for the original picture, the processed picture, the model’s chances for each category, and one sampled summary. Compare the results with the slide and point out that the terminal also shows the processed picture. The command reads a tracked snapshot of completed results. It requires only Python 3. For a no-terminal version, cover the percentages on a printout or point to each bar in turn after the group commits to a guess.

## Optional engineering detail

- **Seeing, keeping, and using a clue are different tests.** A clue may affect a model’s numbers. A *probe* measures whether a separate reader can recover it on held-out mazes. A choice test asks whether the trained agent uses the clue to turn. Ask older Scouts how they would stop the reader from memorizing particular maze layouts.
- **The first drop in the tested T-maze agents occurred at the compact categorical state.** An *encoder* turns the picture into numbers. Both those features and the model’s *posterior probabilities* (its estimated chances for each category after seeing the picture) gave the linear reader 100% at reset across the three seeds. Selecting the most likely categories (*argmax*) gave identical states for opposing cues. Drawing categories using their probabilities is *categorical sampling*. The sampled-state probe scored about 50%. Under the paired test assumptions, the best possible accuracy from one draw was bounded above by 50.07–50.18% across seeds. Imagine two bags with almost the same mix of LEFT and RIGHT slips. Seeing the exact mix may tell you which bag you have, while pulling a single slip tells you very little. Small probability differences can be meaningful to a reader with access to the full distributions and carry negligible information in one draw.
- **The turn test used selected starting states.** It checked behavior with a readable signal present in the running summary (the *recurrent state*). The signal may differ from one the agent normally produces. Chance-level turns establish the measured choice outcome in this setup. Small shifts in predictions or action preferences can still occur without changing the turn taken.
- **The simulator comparison has a different scope.** CAGE2 offers only a partial view of the simulated network. Its scores describe frozen agents under one protocol. The bounded memory study found too few comparable histories to measure the added value of memory. These studies establish simulator-level evidence only. The categorical result applies to the tested T-maze checkpoints.

## Explore AI together

Explore AI with your parent or guardian, or work with an Artificial Intelligence merit badge counselor at a troop meeting. Keep names, credentials, private files, and network details out of prompts. Use made-up data, an approved simulator, or a local toy project. Review suggestions together and start with a test that could reveal a mistake.
