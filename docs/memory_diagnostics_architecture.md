# Frozen memory diagnostics architecture and CAGE2 compatibility

**Assessment.** The existing tools support a shared offline diagnostics library in `dreamerrl/eval/`. Start with one flat Dreamer adapter and keep the T-maze and CAGE2 collectors at the environment boundary. There is enough CAGE2 data for an archive-only compatibility test. A hidden-state investigation requires a small labeled replay validation before a larger collection.

## Two adapter boundaries

These are callable contracts for the first implementation. Plain data records and an explicit stage registry are sufficient.

| Boundary | Contract |
|---|---|
| Environment | `schema()` provides observation shape and encoding, action mapping, horizon and environment revision. `collect(request, policy)` returns ordered episodes with raw observations, incoming action, reset/terminal/truncation flags and stable episode IDs. A separate label join returns values and validity masks keyed by episode and observation index, optionally host or target ID. A task hook declares known event times, valid matched pairs, controls and success metrics. |
| Model | `load(checkpoint_spec, env_schema)` checks a trusted local file hash, source/format, architecture, budgets and schema before strict state-dict load. `initial_state()` and `filter_step(state, model_input, incoming_action, is_first, latent_mode, rng)` produce named representations and opaque carry. `imagine_step(state, action, latent_mode, rng)` advances under the prior. `readouts(state, policy_carry)` returns the supported actor distributions and critic readout. Capabilities identify absent stages and policy carry requirements. |

Use separate execution records for policy-visible frames and offline labels. The shared engine joins labels after extraction and keys features by checkpoint, episode, observation index, latent mode and draw. Group related episodes, paired histories and repeated draws before splitting. Keep boundary flags and availability masks in the record. At frame t, the model sees observation t and action t−1. The actor selects action t after filtering. Reward for action t and its resulting frame belong to the outgoing transition. At reset, previous action and carry are cleared. Posterior z can respond to the reset observation immediately, and the ensuing transition can pass that effect into h.

Use separate representations for raw posterior logits, pre-unimix softmax, post-unimix probabilities and hard categorical state. The public Dreamer `logits` field contains log mixed probabilities when unimix is enabled. Capture the raw tensor at the posterior head and test it against the public probabilities. Record matching RNG seeds and whether draws share noise. Shared noise preserves the marginal draw and supports paired sensitivity, while the resulting distance depends on the coupling. Calculate factor-level JS and entropy on the categorical axes before summarizing. Keep per-seed and episode-level uncertainty distinct.

## CAGE2 labels and compatibility

**Primary label.** For each host in the verified Blue host order, use whether the simulator has an active Red session on that host at the pre-action frame. Read the pinned simulator's session state through a diagnostic-only adapter. Define disappearance only from a later truth snapshot. Secondary labels can include time since first or last active-session event and host or subnet session burden. Validate semantics on a small fixture with known live, inactive and removed sessions. Host privilege tiers require a separate check of simulator usernames and session types. Retain masks for missing or ambiguous labels. BlueTable activity and compromise codes describe defender-visible beliefs and are useful as covariates or visible-evidence controls. Reward components measure outcomes.

**Timing.** [The CAGE2 wrapper](../dreamerrl/env/cage2/cage2_env_wrapper.py) returns the new reset frame in `state` on same-step reset and preserves the completed episode's frame in `transition_state`. Capture truth at the simulator step before auto-reset or use a diagnostic-only wrapper around the same pinned simulator. Check parity with the archived action, reward and boundary sequences. The 30-step cap is normally a truncation and the reset frame belongs to the next seed. Independent opponent runs can have distinct state and action histories despite sharing seeds.

**Schema and reads.** CAGE2 uses a serial 52-value Blue vector and 145 actions. Validate the full action mapping, ordered hosts and subnets, scenario fingerprint and opponent identity. The original v4 baseline has a flat encoder. The host-aware cohort uses per-host preprocessing and pooling. MiniHack uses categorical glyph lookup and a spatial network. Capture the actual checkpoint encoder path and keep decoder scoring optional. The first CAGE2 pass should use a flat actor. For v5 policy tests, preserve the higher-level goal and interval state across steps and compare complete policy decisions. Calling the low-level worker alone changes the readout. Report the identity of any critic used and compare its scalar readout on the same states. Prior mode and prior sampling are separate open-loop conditions.

**Environment pins.** Use the lockfile and Git revision appropriate to the checkpoint, then record the exact dependency and vendor revisions. The maintained CAGE2 profile uses Gymnasium 1.4.0 and the pinned CybORG vendor, while the MiniHack legacy profile uses Gymnasium 1.2.0 with NLE 1.3.0. The root lock pins Torch 2.9.1 and NumPy 1.26.4. Keep the historic baseline isolated under `.baseline/` and use the recorded historical lock for its checks. Avoid new dependencies for this integration.

## Minimal integration and readiness

1. **Shared core and parity.** Migrate the common array-only functions once. Unit-test an exact paired collapse, a weak mixed posterior, reproducible categorical marginals, a linearly separable target, XOR recovery, an episode-group label permutation, and zero sensitivity under identical histories. Test that validation chooses hyperparameters and that modifying held-out labels leaves the fitted probe unchanged. Compare with the existing ridge implementations under their recorded conventions.
2. **Adapter contract tests.** Use a short synthetic episode with a cue at reset, a delayed target and a same-step reset. Assert frame/action/label alignment, state reset, RNG repeatability, action schema rejection and that labels cannot reach model inputs or actions. In the locked MiniHack profile, run one lightweight T-maze fixture through both old and new extraction paths and compare hard states and probe inputs at reset and junction. Match exactness or a documented floating-point tolerance. Test loss of raw-logit capability explicitly for old cached artifacts.
3. **CAGE2 archive and label pilot.** Intake the pilot NPZ as a regression fixture for shape, grouping and historical forecast parity. For hidden-state work, predeclare one matched flat final and a B-line subset with a fixed small CPU cap, for example 24 archived seeds for collection validation. Replay its saved Blue actions and validate trace and label parity, host coverage, and per-episode positive/negative support. Use this pilot to validate the adapter and set a sample budget. It is too small for a definitive comparison. Larger evaluation requires a fresh held-out seed range or a predeclared untouched group.
4. **First scientific comparison after validation.** For encoding, use a visible-evidence auxiliary target and compare the current vector with the embedding. For compression, compare posterior probabilities with argmax and sampled z at the same frame. For memory, test whether adding h or hz improves host session detection over current observation plus time and a reset-history control. Start with one regularized linear probe and a predeclared RBF sensitivity check. Group splits by episode seed, keep alternate opponents on the same split if included, and assess balanced accuracy and average precision with prevalence and paired episode bootstrap intervals. For utilization, hold the current observation and previous action fixed and compare the actor distribution and critic under factual and history-truncated carries. Carry interventions are sensitivity tests; verified observation-matched simulator histories are required for stronger task claims. An identical-history run and a time-only baseline are required controls.

**GO** for shared-core implementation, synthetic parity fixtures and archive intake. **Conditional GO** for the bounded CPU label pilot after schema and action-replay checks are in place. **NO-GO** for broad CAGE2 evaluation, hierarchy comparisons or GPU execution until the pilot verifies label timing, positive support and artifact reuse. The current assessment used static review. It launched no diagnostic or training process.
